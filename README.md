# UDA Final Project — Forage Biomass Prediction from Remote Sensing

This repository contains the final project for **Unstructured Data Analysis (UDA)**.  
The project implements an end-to-end remote-sensing pipeline that uses **Sentinel-2 imagery and DEM data** to learn spatial representations in a **self-supervised manner**, and then predicts a **map-derived forage biomass proxy** over semi-arid rangelands in **Chihuahua, Mexico**.

The core idea is to avoid reliance on dense field measurements and instead exploit spatial structure in unstructured geospatial data.

---

## Project Purpose

The objectives of this project are:

- Build a **scalable and reproducible pipeline** for biomass estimation using freely available satellite data.
- Learn **spatial representations** from multispectral imagery via a **self-supervised CNN** (Stage A).
- Aggregate patch-level embeddings and predict **tile-level biomass proxies** using a simple and interpretable regression model (Stage B).
- Produce **geographical visualizations** and **quality summaries** for validation and interpretation.

This setup reflects real-world constraints in rangeland monitoring, where ground-truth biomass measurements are sparse, expensive, or unavailable.

---

## Technical Overview

The pipeline consists of four main stages:

1. **Data acquisition and tiling**  
   Sentinel-2 L2A multispectral imagery and DEM data are downloaded and stored as georeferenced tiles.

2. **Self-supervised representation learning (Stage A)**  
   A lightweight CNN is trained to predict Canny edge maps derived from vegetation-related indices, forcing the encoder to learn meaningful spatial structure without labels.

3. **Proxy regression (Stage B)**  
   Patch embeddings are aggregated per tile and used to train a Ridge regression model against a map-derived biomass proxy.

4. **Visualization and quality checks**  
   Pasture fractions, DEM summaries, and geographical plots are generated to support interpretation and sanity checks.

## Folder and File Descriptions

### `dataset/`
Stores all downloaded geospatial data, including Sentinel-2 and DEM tiles.  
These files are generated by the data-wrangling stage and serve as inputs for training and evaluation.

### `outputs/`
Contains all generated outputs from the pipeline:
- Stage A training plots (loss and edge quality)
- Stage B regression plots and histograms
- Scatter plots and saved figures
- Intermediate and final prediction artifacts

### `processing/`
Contains the main executable scripts of the pipeline:
- `data_wrangler.py`: downloads and prepares Sentinel-2 and DEM tiles
- `pastizales.py`: computes natural pasture fractions and DEM summaries
- `vegetation.py`: produces geographical tile and vegetation plots
- `training.py`: runs the full two-stage learning pipeline (Stage A + Stage B)

All scripts read parameters exclusively from the shared configuration file.

### `quality/`
Stores quality-control artifacts:
- CSV tables with pasture fractions and elevation statistics
- High-resolution geographical plots of tiles and regions

### `utilities/`
Shared helper functions used across the project, including:
- JSON configuration loading
- Tile listing and raster reading
- Proxy biomass loading and alignment
- Common formatting and utility routines

### `requirements.txt`
Lists all Python dependencies required to run the project, including geospatial libraries, scientific computing packages, and deep-learning frameworks.

### `LICENSE`
Apache-2.0 license governing the use and distribution of this repository.

---

## Configuration

All parameters are defined in a **single JSON configuration file** located under `utilities/`.

The configuration includes:
- Copernicus Data Space API endpoints
- Authentication variables
- Tile definitions and bounding boxes
- Output paths and filenames
- Training hyperparameters
- Visualization and quality settings

No parameters are hard-coded inside the scripts.

## How to Run

### 1. Clone the Repository

git clone https://github.com/amcm329/uda_final_project_castillo.git
cd uda_final_project_castillo

### 2. Install Dependencies
pip install -r requirements.txt

System-level dependencies for geopandas, rasterio, and cartopy (GDAL, PROJ) must be available.

### 3. Set Authentication

Export Copernicus credentials as environment variables referenced by the configuration file.

export CLIENT_ID=your_client_id
export CLIENT_SECRET=your_client_secret
